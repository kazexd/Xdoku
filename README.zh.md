# xdoku

使用 Expo 與 TypeScript 在 Windows 開發的 iPhone 貓咪邏輯遊戲。名稱與美術尚未定案。

## 開發

使用 Node.js 22.16 或更新版本。在 `mobile` 執行 `npm ci`，再執行 `npm start`。在 iPhone 使用相容的 Expo Go 或開發建置。`npm run web` 可開啟瀏覽器版本。

以 `npm test`、`npm run typecheck` 與 `npm run lint` 驗證。測試涵蓋每一個隨 App 發佈的題目、生成器、資料載入、UTC 每日選題、題庫用盡、錯誤資料處理及放置規則。仍須進行 iPhone 實機測試。

依賴稽核目前在 Expo CLI 間接使用的 node-forge／zod 套件中回報五項高嚴重性問題。相容的自動修正未能清除，發佈前須重新評估上游更新。

## 狀態與路線

已實作：自動選擇 7×7、8×8、9×9 或 10×10 唯一解棋盤、編號關卡、UTC 每日棋盤、單擊排除記號、雙擊放貓咪、衝突回饋、開新一局、揭示、重玩及本機儲存。不提供尺寸選擇器或復原按鍵。「開新一局」前往下一個一般關卡（包括從每日模式開新局），「重新開始」則重玩目前題目；App 只讀取預先建立的 JSON 資料：200 個一般關卡及獨立的 365 題每日題池。一般關卡順序固定，每日題目按 UTC 日期選取，365 天後明確循環。一般題庫用完會停用「開新一局」，不即時生成或靜默重複。目前介面為繁體中文。

可在棋盤上拖曳以快速編輯記號。從空白格開始，整次拖曳固定為加入記號；從排除記號開始，整次固定為清除記號。貓咪不會被改動，從貓咪開始拖曳不會塗改。快速拖曳會補上經過的格子，重複經過不會切換狀態，整次拖曳作為一次編輯。中斷拖曳會捨棄預覽。手指輕微移動仍視為點擊。觸摸棋盤時會暫停頁面捲動，請從棋盤外捲動頁面。螢幕閱讀器可使用各格的切換記號／貓咪輔助動作。

每個色區使用十色調色盤中的獨有顏色。衝突以紅色外框及驚嘆號標示，並保留原本的色區底色。配色測試檢查兩兩 CIELAB 色差與記號對比；色覺差異的可用性仍需使用者測試。

新版生成器（v6）完全不預放貓；7×7、8×8、9×9、10×10 的每色硬上限分別為 11、13、15、17 格，最多一個單格色區。現有 v5 題庫會保留至新題庫完整生成，App 同時支援兩個版本。

開發用生成器先固定合法答案，再交換或轉移色區邊界，保持連通性、面積與每區一隻答案貓。只接受無預放貓、唯一解且推理評估器能完成的題目；搜尋失敗會換種子，絕不補貓或放寬上限。

推理評估使用單一候選及群組共同衝突排除，難度按群組排除次數評估（0 次簡單、1–3 次中等、4 次以上困難）。建置工具排除旋轉、鏡像及色區重新編號後的重複。App 不匯入生成或搜尋程式。

由題目內容計算的 ID 讓一般進度繼續對應同一題。每日存檔鍵亦包含 UTC 日期，因此年度循環會由新進度開始。舊版存檔仍保留在裝置，但不套用新版棋盤。上架前仍需加入解釋型提示、多語系、不依賴顏色的區域識別、原創素材及裝置測試，包括舊款 iPhone 的啟動效能。

排行榜需要可信任後端與分數驗證，並區分使用提示的紀錄。購買功能需要 Apple 商品、權益驗證及回復購買。目前兩項服務均未串接，不收取款項，也不提供虛構排名。

發佈需要 Apple Developer 與 Expo 帳號、正式 bundle identifier、EAS 設定、簽署、TestFlight 測試、隱私揭露、支援與隱私頁面、商店素材及送審。此原型尚未達到送審標準。請勿將憑證放入 Git。

## 預先建立題庫

在 `mobile` 執行 `npm.cmd run puzzles:generate -- --classic 200 --daily 365 --seed 100000 --max-seeds 20000 --attempts 500`。每個種子最多搜尋 500 批，整次最多 20,000 個種子；每題目標尺寸由固定種子選取，失敗不會改填其他尺寸。每個種子後儲存 `.puzzle-generation/checkpoint.json` 並輸出進度，相同指令可續跑。用盡預算可增加 `--max-seeds`；其他設定需一致，或以 `--checkpoint <新路徑>` 開始新工作。10×10 較難找到，不保證預算內可填滿。只有完整通過驗證才替換 `src/data/puzzles.json`，中斷或失敗保留舊題庫。生成完成後提交 JSON。

已發佈的題目排序屬於版本資料：編輯題庫時保留既有一般題目與每日排序。修改每日題池長度或順序會改變日期映射，應作為新的排程規劃。目前有限的每日題池每 365 天循環。舊版即時生成關卡的存檔仍保留，但不會套用至新題庫。
