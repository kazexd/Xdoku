# xdoku

使用 Expo 與 TypeScript 在 Windows 開發的 iPhone 貓咪邏輯遊戲。名稱與美術尚未定案。

## 開發

使用 Node.js 22.16 或更新版本。在 `mobile` 執行 `npm ci`，再執行 `npm start`。在 iPhone 使用相容的 Expo Go 或開發建置。`npm run web` 可開啟瀏覽器版本。

以 `npm test`、`npm run typecheck` 與 `npm run lint` 驗證。測試涵蓋每一個隨 App 發佈的題目、生成器、資料載入、UTC 每日選題、題庫用盡、錯誤資料處理及放置規則。仍須進行 iPhone 實機測試。

依賴稽核目前在 Expo CLI 間接使用的 node-forge／zod 套件中回報五項高嚴重性問題。相容的自動修正未能清除，發佈前須重新評估上游更新。

## 狀態與路線

已實作：自動選擇 7×7、8×8、9×9 或 10×10 唯一解棋盤、編號關卡、UTC 每日棋盤、單擊排除記號、雙擊放貓咪、衝突回饋、開新一局、揭示、重玩及本機儲存。不提供尺寸選擇器或復原按鍵。「開新一局」前往下一個一般關卡（包括從每日模式開新局），「重新開始」則重玩目前題目；App 只讀取預先建立的 JSON 資料：200 個一般關卡及獨立的 365 題每日題池。一般關卡順序固定，每日題目按 UTC 日期選取，365 天後明確循環。一般題庫用完會停用「開新一局」，不即時生成或靜默重複。目前介面為繁體中文。

可在棋盤上拖曳以快速編輯記號。從空白格開始，整次拖曳固定為加入記號；從排除記號開始，整次固定為清除記號。貓咪不會被改動，從貓咪開始拖曳不會塗改。快速拖曳會補上經過的格子，重複經過不會切換狀態，整次拖曳作為一次編輯。中斷拖曳會捨棄預覽。手指輕微移動仍視為點擊。螢幕閱讀器可使用各格的切換記號／貓咪輔助動作。

每個色區使用十色調色盤中的獨有顏色。衝突以紅色外框及驚嘆號標示，並保留原本的色區底色。配色測試檢查兩兩 CIELAB 色差與記號對比；色覺差異的可用性仍需使用者測試。

目前 App 仍使用已驗證的 v6 題庫（200 題一般、365 題每日），保持原有面積規則。新的開發用 v7 生成器改為普通色區面積介乎行數 50%～200%，下限向上取整：7×7 為 4～14、8×8 為 4～16、9×9 為 5～18、10×10 為 5～20 格。每題在生成前指定「沒有單格」或「恰好一個單格」；單格例外不受普通下限限制，其餘色區全部遵守上下限。

開發用生成器先固定合法答案，再交換或轉移色區邊界，保持連通性、面積與每區一隻答案貓。只接受無預放貓、唯一解且推理評估器能完成的題目；搜尋失敗會換種子，絕不補貓或放寬上限。

推理評估使用單一候選及群組共同衝突排除，難度按群組排除次數評估（0 次簡單、1–3 次中等、4 次以上困難）。建置工具排除旋轉、鏡像及色區重新編號後的重複。App 不匯入生成或搜尋程式。

由題目內容計算的 ID 讓一般進度繼續對應同一題。每日存檔鍵亦包含 UTC 日期，因此年度循環會由新進度開始。舊版存檔仍保留在裝置，但不套用新版棋盤。上架前仍需加入解釋型提示、多語系、不依賴顏色的區域識別、原創素材及裝置測試，包括舊款 iPhone 的啟動效能。

排行榜需要可信任後端與分數驗證，並區分使用提示的紀錄。購買功能需要 Apple 商品、權益驗證及回復購買。目前兩項服務均未串接，不收取款項，也不提供虛構排名。

發佈需要 Apple Developer 與 Expo 帳號、正式 bundle identifier、EAS 設定、簽署、TestFlight 測試、隱私揭露、支援與隱私頁面、商店素材及送審。此原型尚未達到送審標準。請勿將憑證放入 Git。

## 預先建立題庫

在 `mobile` 執行 `npm.cmd run puzzles:generate -- --per-case 400 --seed 100000 --max-seeds 200000 --attempts 500`。尺寸 7～10 各分有／無單格兩組，預設每組 400 題，共 3,200 題。輸出為 `generated-puzzles/v7/` 下八個 JSON（例如 `7x7-no-singleton.json`、`7x7-one-singleton.json`）及 `manifest.json`；每檔包含條件、目標、已驗證題目與 `complete`。不分配一般／每日題池，也不替換 `src/data/puzzles.json`。

已發佈的題目排序屬於版本資料：編輯題庫時保留既有一般題目與每日排序。修改每日題池長度或順序會改變日期映射，應作為新的排程規劃。目前有限的每日題池每 365 天循環。舊版即時生成關卡的存檔仍保留，但不會套用至新題庫。


每局有三條魚（🐟）。在答案以外的位置放貓，會先顯示貓、閃暗紅色，再變成 X 並扣一條魚；回饋期間暫停輸入。剩餘魚數隨進度儲存，零條魚時顯示 Game Over 並提供「開新一局」。重新開始會重設同一題及三條魚，做記號與提示不扣魚。一般題庫用盡時，Game Over 提供重新挑戰本關。

選錯的格子會鎖定為 X，該局內不能透過點擊、拖曳或輔助動作修改。鎖定狀態隨進度儲存，重新開始或開新一局才會清除。沒有錯誤紀錄的舊存檔無法還原先前選錯的格子。

已找到的正確貓咪（包括提示揭示的貓）放下後即鎖定，載入存檔後仍不能修改；重新開始或開新一局才會清除。

完成關卡後會鎖定棋盤，最後一隻貓輕彈並播放短暫彩紙，再顯示祝賀、剩餘魚數與提示使用紀錄。玩家按「下一關」才開始新局；每日完成後可繼續漫遊關卡。最後一個一般關卡顯示題庫完成祝賀，並可查看完成棋盤。提示紀錄隨進度儲存，重新開始會清除。

每次新放下正確貓咪會播放原創、柔和的 0.28 秒上行提示音，以 expo-audio 隨 App 打包並可離線使用。提示揭示亦會播放；既有貓咪、記號、錯誤及載入存檔不觸發。音效尊重 iPhone 靜音模式並與其他音訊混合，不啟用錄音或背景音訊權限。

直向遊戲採單屏版面，不提供捲動。畫面會量度安全區容器、上方資訊與按鈕高度，正方形棋盤取剩餘寬高並以 432 點為上限；小螢幕優先減少留白，操作按鈕保留至少 44 點觸控高度。棋盤符號按格子尺寸縮放，說明文字保留系統字體放大。詳細操作、規則、目前小筆記及後續旅程移入右上角選項。選項與結果彈窗按文字實際高度分頁，完整保留內容；每次開啟選項回到第一頁，彈窗使用自己的安全區。

版面驗證：執行既有測試與 Web 匯出後，在 `mobile` 執行 `node tools/check-layout.mjs`，需有 Playwright 及 Edge。若 Playwright 由開發環境提供而非本機套件，可將 `PLAYWRIGHT_MODULE` 設為該模組的絕對目錄。瀏覽器檢查涵蓋 320×568、375×667、390×844、430×932，一般及放大的 Web 文字、選項分頁、縮放後棋盤輸入與下一關流程。原生 iPhone 安全區、Dynamic Type、觸控及音訊仍須實機測試。


輪流搜尋八組，跨組排除旋轉、鏡像與色區重新編號的重複；所有題目仍須色區連通、不預放貓、唯一解及可推理解完。每個種子最多 500 批變動，整次最多 200,000 個種子，並不保證填滿，無單格的 9×9／10×10 特別困難。新增題目立即寫入 `.puzzle-generation/groups-v7.json` 斷點及該組輸出；連續失敗每 25 個種子保存一次，中斷最多重算 24 個失敗種子。重新執行相同指令續跑，用盡預算可增加 `--max-seeds`；起始種子、每種子批數及生成器版本需一致；可更改 `--per-case` 並保留已有題目。部分成果亦會保留，只有八組全部填滿才顯示完成；舊版斷點不適用。

啟動時會合併斷點與既有分組 JSON，重新驗證內容與跨組去重，並顯示每組 `SKIP`（已達目標）或 `RESUME`（補足差額）。沒有斷點時可從分組檔及 manifest 恢復已有成果與種子進度；舊版 manifest 沒有排程游標時保守恢復排程。若連 manifest 也沒有，會保留題目並以已收錄題數作種子起點，可能重試舊種子但不重複收錄。以實際題數判斷完成，不信任檔案內的舊完成標籤；超出目標的題目亦不刪除。損壞或設定不相容的檔案會報錯並保留，不能靜默覆蓋。`--max-seeds` 仍是累計搜尋上限，用盡後增加該值即可繼續。
